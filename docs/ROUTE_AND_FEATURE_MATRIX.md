**Column notes**:
- **Current component**: Server or Client Component, plus approximate size where notable.
- **Required data**: Hasura queries referenced directly in the `page.tsx` (child client components may issue additional queries not captured here — this is a page-level skim, not exhaustive).
- **Actions**: mutations/API calls/action buttons found in the page file or its immediately named action-button components (e.g. `CancelBillButton`). List screens whose row-level actions live in a separate table component (e.g. `BillRow.tsx`, `JobWorkTable.tsx`) are noted as such.

## Cross-cutting observations for the redesign

1. **86 rows, 1 real Classic/Modern duplication.** Only `/dashboard` needs page-body reconciliation work when collapsing `existing`/`classic`/`modern` to two modes. The other 85 routes need only the shared `CHROME` class-string table in `src/app/(app)/layout.tsx` trimmed from 3 entries to 2.
2. **Zero route-level test coverage.** Every one of the 86 rows is "No test coverage" — the redesign will be adding/changing UI with no regression safety net at the component level (only two library-code test suites exist, and both are currently broken — see audit §13).
3. **4 routes have a real auth-gate gap**: `/accounts`, `/purchase-cancellations` (+`[id]`), `/sale-cancellations` (+`[id]`), `/profile` are missing from `src/proxy.ts`'s `APP_PATH_PREFIXES`, unlike every other sidebar destination.
4. **Only 8 of 86 routes have any explicit role/permission check** beyond "logged in": the 6 Data Integrity pages, `/admin/roles` + `/admin/roles/new`, `/jobwork-transfers`, and `/reports/item-ledger`. Everything else — including all financial/transactional screens (Purchase Entry, Sale Entry, Job Work, Transfers, Accounts) — is equally writable by any authenticated role today.
5. **2 routes exist but aren't reachable from the 16-item sidebar** at all: `/jobwork-transfer-cancellations` and its `[id]` detail (only reachable by drilling in from `/jobwork-transfers`). Worth deciding during the redesign whether these need their own nav entry or should stay a drill-in-only screen.
